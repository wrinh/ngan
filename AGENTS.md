# AGENTS.md

Instructions for AI agents working in this repository.

## What this is

**ngan** — a Praat-compatible acoustic analysis engine in pure MoonBit, compiled to WebAssembly GC. Ports Praat's `To Intensity...`, `To Pitch (ac/cc/filtered ac)...`, `To Formant (burg)...`, `To Spectrogram...`, `To PowerCepstrogram...` / `Get CPPS...`, `To MFCC...` / Mel / Bark spectrograms, Voice Report, and TD-PSOLA manipulation.

Derived from Praat's GPL-3+ C++ sources → **the whole repo is GPL-3.0-or-later**. Do not introduce code copied from non-compatible sources; every `.mbt` file carries an SPDX header (keep it when creating new files). `docs/spec.md` is the original requirements doc; where it disagrees with actual Praat behavior, Praat wins — see the "Praat parity notes" section of `README.mbt.md` before touching `analysis/`.

## Layout

- `lib.mbt` + `lib_test.mbt` — root facade: `analyze_intensity`, `analyze_pitch`, `analyze_formants`, `analyze_spectrogram`, `analyze_all`; re-exports via `pub using`.
- `types/` — shared result structs (`IntensityTier`, `PitchTier`, `FormantTier`, `Spectrogram`, ...). Public types live here, not in internal packages.
- `math/` — Complex, Bessel I0, Durand-Kerner roots, libm re-exports (`wrinh/ngan/math`, alias `@math`).
- `dsp/` — radix-2 FFT (`FftPlan`), Kaiser/Hann/Gaussian windows, sinc resampler, Burg LPC.
- `analysis/` — the four Praat ports (`intensity.mbt`, `pitch.mbt`, `formant.mbt`, `spectrogram.mbt`).
- `web/` — WasmGC FFI boundary package (`web.mbt` with `link wasm-gc exports`) producing `web.wasm` for `@wrinh/ngan` (`npm/`).
- `npm/` — TypeScript SDK (`@wrinh/ngan`), Web Worker wrapper, chunked long-audio analysis, and AudioWorklet streaming.
- `cmd/main/` — CLI demo over a synthetic vowel.
- `.github/workflows/` — `ci.yml` (check all targets, test, build, run demo, build & test npm SDK).

## Commands

```bash
moon check --target all   # typecheck (also catches wasm-gc-only issues)
moon test                 # 25 tests; README.mbt.md doc blocks are tests
moon test -u              # update inspect snapshots after intended changes
moon fmt && moon info     # format; regenerate *.mbti (commit mbti diffs)
moon run cmd/main         # CLI demo
moon build --target wasm-gc --release   # artifact in _build/.../web/web.wasm
```

## Conventions & gotchas

- Modern MoonBit: `moon.mod` / `moon.pkg` (not the legacy JSON forms); imports are declared per-package in `moon.pkg`, referenced as `@math.xxx`, `@dsp.xxx`; separate top-level items with `///|`.
- Numeric style: `x.sqrt()` method form; `Double -> Int` via `.to_int()`; `@math.ln/log2/log10`; labeled args are `name~` in signatures, `name=value` (or bare `name~`) at call sites. String interpolation `\{...}` must stay on one line.
- Ranges with computed bounds need parentheses: `0..<(n - 1)`.
- Frame conventions everywhere: Praat `Sampled_shortTermAnalysis` (symmetric fit, `t1 = mid - 0.5*n*dt + 0.5*dt`); don't "simplify" these formulas — tests pin them.
- `pkg.generated.mbti` files are generated (`moon info`) and committed; never hand-edit.
- The wasm module imports its string literals as `externref` globals from module `_` (import name = literal) and needs `WebAssembly.compile(bytes, { builtins: ['js-string'] })` — see `npm/src/loader.ts` `loadNganWasm()`. No JS glue is generated by moon.
- Never subsample spectrogram time frames without averaging linear power first (aliasing of glottal striations — this was a real bug once).
- Demo signal synthesis: glottal pulse amplitude must depend on samples since the last pulse, not fractional phase (amplitude jitter breaks pitch tracking).
- GitHub remote is `wrinh/ngan` (org); module name must match.
